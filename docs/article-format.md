# 阅读题 article 字段格式规范

`question_groups.article` 存的是**阅读/完形题的文章正文**，所有阅读题型共用这一列
（reading_short/mid/long/thesis/integ、text_grammar 完形、info_search）。

它不是「能直接上屏的 HTML」，而是**带语义标记的半成品**：爬虫按本规范产出，前端
`renderArticle()`（`student/src/views/ExamView.vue` 与 `ResultView.vue`，两处逻辑必须一致）
按本规范翻译成最终 HTML。**爬虫能产出的标记 = 前端能识别的标记**，这是一份双方共同遵守的
合约。任何一方多写或少写，都会导致原文错乱或标记裸露。

手改 `data/raw/*.json` 的 `article` 时，照本规范判断该用哪种包裹。

---

## 判断总原则：语义 vs 排版

对源页面里的每一块内容，先问一句「它承载的是**我们需要的语义**，还是**源站的排版**」：

| 情况 | 处理 |
|------|------|
| 承载语义，且纯文本能表达 | 降成纯文本 / 轻量标记（`【U】`、`\n` 等） |
| 承载语义，但纯文本表达不了（跨行跨列、格内换行的表格） | 保留成**重建的**白名单 HTML（仅 `<table>`） |
| 纯粹是源站排版/样式（`style`、`align`、`class`、`<h1>` 字号等） | 丢弃，只留文字 |

> 优先降维成文本或标记，保持各题型一致、可控、无 XSS 面。**只有表格是唯一例外**。

---

## 标记速查表（前端只认这些）

| 标记 | 含义 | 何时用 | 渲染结果 |
|------|------|--------|----------|
| `【U】…【/U】` | 下划线词 | 原文有下划线、且问句会引用它 | `<u class="reading-underline">…</u>` |
| `【BOX】…【/BOX】` | 边框信息块 | 源页面里带边框的通知/须知块（募集要项、案内等） | `<div class="info-box">…</div>`，内部 `\n`→`<br>` |
| `【文章A】` / `【文章B】` | 综合理解双篇标题 | 仅 reading_integ（统合理解）分栏两篇 | `<div class="article-label">文章A</div>` |
| `（N）` / `（Na）` | 完形填空空号 | 仅 text_grammar 完形题的空位 | `<span class="cloze-blank">（N）</span>`（高亮） |
| `<table>…</table>` | 结构化表格 | 表格含跨行跨列、或单元格内换行，纯文本表达不了 | 原样交浏览器渲染（转义时被保护） |
| `\n`（换行符） | 段落/行分隔 | 段落之间、块内换行 | `<br/>` |

**表里没有的一律不要用。** 想新增一种标记，必须同时改爬虫产出 + 两个视图的 `renderArticle`
+ 对应 CSS，否则标记会原样裸露给用户。

---

## 各标记的判断细则

### `【U】…【/U】` 下划线
- **用于**：源页面 `<u>…</u>`，通常是问句里「下線部について」引用的那个词/句。
- **成对**：`【U】` 和 `【/U】` 必须成对，且不嵌套。手改时数量要对齐。
- **不要用于**：单纯想强调某词。只有原文确实是下划线、且题目引用时才标。

### `【BOX】…【/BOX】` 边框块
- **用于**：源页面里 `border-style:solid` 的 `<div>`/`<p>`，即视觉上被方框圈起来的一段
  （募集要项、応募規定、ご案内正文等）。
- **成对**，可多个并列（如信息检索题里几门课程各一个 `【BOX】`）。
- **内部换行**：块内的 `\n` 会渲染成 `<br>`，所以块内保留原始分行即可。
- **不要嵌套** `【BOX】` 于 `【BOX】` 内。

### `【文章A】` / `【文章B】` 双篇标题
- **仅** reading_integ（综合理解/統合理解）使用：两篇文章就同一话题各自表述。
- 单独成行，放在各自那篇正文的**上方**。
- 其他题型出现它属于误标，应删除。

### `（N）` 完形空号
- **仅** text_grammar 完形题使用。爬虫（test_type_5）已把历史上的
  `（N）`/`【N】`/`__N__`（全/半角、带 `-字母`后缀）统一归一化成**全角括号** `（N）`。
- 前端**只认全角括号** `（\d+[a-zA-Z]?）`。手改时务必用全角 `（）`，半角 `()` 不会高亮。
- 成对空写作 `（4a）`/`（4b）`。

### `<table>` 表格（唯一允许的 HTML）
- **仅当**表格「纯文本/Markdown 表达不了」时才用 HTML：合并单元格（rowspan/colspan）、
  或单元格内有换行。简单规整的小表也可以，但要遵守下面的白名单。
- **白名单**：只允许 `<table class="info-table">`、`<thead>`、`<tbody>`、`<tr>`、
  `<th>`、`<td>`（可带 `rowspan`/`colspan`）、`<caption>`、单元格内 `<br>`。
- **禁止**：`style`、`align`、`class`（除 `info-table`）、`<script>`、`<img>`、事件属性
  （`onerror` 等）、外链。爬虫的 `_table_to_html` 是「白名单重建」而非复制源表格，手写时同理。
- **转义豁免**：`renderArticle` 会先把 `<table>…</table>` 抠出保护、转义其余文本、再还原。
  所以只有 `<table>` 块内可以出现 `<`/`>`；正文其它地方的 `<`/`>`/`&` 都会被转义成字符显示，
  **不要在表格外写任何 HTML 标签**（会变成可见的 `&lt;p&gt;` 之类）。

---

## 常见错误对照

| 症状 | 原因 | 修法 |
|------|------|------|
| 表格显示成一堆 `\| a \| b \|` 文字 | 用了 Markdown 表格语法（旧方案，已废弃） | 改成 `<table>` HTML |
| `【U】` / `【BOX】` 原样显示、没生效 | 标记不成对，或写成半角/错字 | 检查开合标记配对、用全角字符 |
| 完形空号不高亮 | 用了半角括号 `(1)` | 改成全角 `（1）` |
| 正文里出现可见的 `&lt;p&gt;` | 在表格外写了 HTML 标签 | 表格外只能用纯文本 + 上述标记，标签删掉 |
| 整段挤成一行、没分段 | 缺 `\n` | 段落之间补换行符 |
| 页面样式错乱 | `<table>` 带了源站的 `style`/`class` | 按白名单清理属性 |

## 改完之后

1. 手改的是 `data/raw/result_XX_checked.json` 的 `article` 字段。
2. 重新入库（信息检索/中长篇等嵌套结构走 `normalize=None`）：
   ```python
   from crawler.spiders.write_to_mysql import _write_passages
   _write_passages("result_XX_checked.json", source="result_XX_checked",
                   category="<题型code>", group_type="reading", normalize=None)
   ```
3. 在学生端强制刷新（Cmd+Shift+R）核对渲染。前端逻辑改动需 `cd student && npm run build`。
